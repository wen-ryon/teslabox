# 系统盘持久化索引：行为与异常边界

## 存储和使用方式

默认目录 `/var/lib/teslabox-system/index-cache/`，由 `TESLABOX_INDEX_CACHE_DIR` 配置。Linux 运行时要求缓存与根文件系统同设备，且不同于录像镜像设备；不满足则禁用持久化，不阻断原有内存索引。测试板已只读确认系统盘为 `/dev/mmcblk0p3`（ext4），录像盘为 `/dev/sda1`（XFS）。不复制视频、快照和挂载状态。

仅保存已成功发布的完整索引及已验证时长证据。后台每 10 秒检查，首次有完整索引即保存，后续最多每分钟保存一次；索引和已校准数量不变时不写盘。断电前最后一分钟的校准可能丢失，重新核对即可，不影响录像。不要宣称重启后无需目录扫描：目录仍要核对，持久化让历史列表先显示，并复用内容验证通过的时长证据。

固定保留一份 `index.json` 和最多一份 `index.pending`，不按设备无限积累。单份数据载荷上限 32 MiB，读取上限 64 MiB，最多 50,000 个单路文件；超限跳过保存而不是截断索引。系统可用空间不足 256 MiB 时停止写入，保留旧缓存。目录创建权限 0700、文件 0600，元数据包含时间和事件位置，按私人数据保护。

页面实际请求过的 `thumb.png` 缓存在 `index-cache/thumbnails/`。缓存按录像盘身份隔离，每张最多 4 MiB、总量最多 256 MiB，不在索引阶段批量读取图片。TeslaCam 每个事件目录只使用一张缩略图；`RecentClips/thumb.png` 也只有一张，但车辆会覆盖更新，因此缩略图 ID 包含相对路径、文件大小、修改时间以及这唯一一张最近缩略图的内容摘要，避免 exFAT 粗粒度时间戳下同大小覆盖仍命中旧图。保存和哨兵事件缩略图只使用属性版本，不批量读取内容。完整索引核对成功后清理当前录像盘已不存在的事件、最近录像旧版本和超出容量的最旧图片；失败或取消的扫描不触发索引一致性清理。

## 异常处理

| 场景 | 处理 |
| --- | --- |
| 首次安装或缓存不存在 | 原有扫描流程，成功后保存 |
| 重启，有匹配缓存 | 先显示历史列表，缓存恢复完成后由服务自动排队创建新快照核对 |
| 车机删除、循环覆盖、新增 | 以新快照的完整目录扫描为准，历史列表不直接播放或删除 |
| 同路径、同大小甚至同修改时间覆盖 | 核对 MP4 时长解析字段的实际字节；不匹配重新校准 |
| 缓存没有足够时长证据 | 可展示历史时长，新扫描不能直接继承 verified |
| 换盘、镜像替换、重新初始化、时区变化 | 数据盘 UUID/序列号/大小、镜像路径/inode/大小、exFAT 卷序列号及车辆时区参与身份；不匹配不加载 |
| 设备断开或未就绪 | 不对外提供历史缓存；恢复后重新核对身份 |
| 设备标识被完整克隆 | 无法仅凭标识识别所有克隆，历史数据仍不能绕过当前内容及快照验证 |
| 新扫描取消、读取失败或副本修复失败 | 不保存半成品、不替换上次完整缓存；沿用扫描重试 |
| 修复快照副本 | 只保存修复并扫描成功的结果，不持久化副本路径 |
| 写入期间断电或进程退出 | 临时文件写完并同步后原子重命名；下次忽略 pending，只读取校验通过的正式文件 |
| 截断、校验和错误、未知格式版本、非法路径/数字/证据范围 | 拒绝整份缓存，退回重建；不因缓存错误中止服务 |
| 系统盘满、只读、权限不足 | 记录警告并限频重试，保留原缓存及内存功能 |
| 文件数或容量超限 | 不写截断缓存；继续内存索引，后续需评估增大预算或分片 |
| 空历史索引 | 响应仍标记 cached，前端继续轮询直到新快照完成 |
| 页面切换或迟到响应 | 快照编号隔离；历史与当前索引不能拼页或混用 |
| 高频快照和校准 | 单缓存写入者、分钟级合并；不开每文件落盘 |

缓存失败不能阻止车机录制。对物理故障、任意磁盘损坏以及硬件不兑现 flush 的情况不承诺绝对可恢复；缓存可丢，原始录像不因缓存操作而改写。

## API 与前端交接

沿用现有鉴权的 `GET /api/v1/video-sessions`。历史响应增加 `cached:true`，各条目也带 `cached:true`，`snapshot_id` 为 `cache:` 命名空间。该编号不是有效快照，禁止用于播放、导出和删除；当前详情接口仍要求真实快照匹配。历史缩略图不从旧挂载路径加载。

```json
{"cached":true,"snapshot_id":"cache:设备身份","items":[],"total":0,"limit":200,"offset":0}
```

服务启动或识别到新的录像盘身份后会自动排队核对；普通历史列表读取仍可补充排队，但不等待扫描完成。`metadata_only=true` 仅读取，不排队。前端历史条目禁用播放和删除；每 5 秒静默获取列表直到响应切换到真实快照（即使历史为空也继续）。保持原本完整录像入口及时间轴方式不变。

`GET /api/v1/storage` 增加可选 `cached_index_at` 和 `cached_video_count`，无真实快照时明确标记“历史索引 · 待核对”，不能标为可播放。校验和用于发现意外损坏，不是对本机恶意管理员的认证签名。

## 验证边界

本地测试覆盖存取、重复原子替换、身份不匹配、损坏文件、越界路径、时长证据复用、同名同大小覆盖、外部删除、空缓存响应、历史操作拦截。需要板端进一步验证真正重启恢复、突然断电、系统盘只读/满盘和 512GB/1TB 实际数据规模；这些不能以单元测试通过代替。
