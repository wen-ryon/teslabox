# TeslaUSB 模拟模式需求

本文档是 TeslaBox 第一项核心功能的需求基线。其他 README、架构和开发计划与本文冲突时，以本文为准。

## 目标

TeslaBox 取代直接连接车辆的普通 Tesla U 盘，通过 ROCK 3A 的 USB Gadget 能力向车辆模拟 USB Mass Storage。车辆持续录像期间，用户可以通过 TeslaBox 网页查看和播放已经写完的 TeslaCam 片段。

这里的“边录边播放”是指：

- Tesla 的录像过程不中断。
- 网页播放已经关闭并可完整读取的 MP4 片段。
- 当前仍在写入的 MP4 不保证可以播放。
- 这不是车辆摄像头的实时视频流。

## 已确认的硬件架构

```text
Tesla 行车记录仪 USB 口
          │
          │ USB Mass Storage
          ▼
ROCK 3A USB OTG Device 口
          │
          │ Linux USB Gadget
          ▼
TeslaCam 虚拟磁盘镜像
          │
          │ 保存镜像、快照和索引
          ▼
ROCK 3A USB Host 口 / M.2 接口 ── TeslaBox 数据盘（U 盘、USB SSD、USB 硬盘或 NVMe）

ROCK 3A microSD/TF 卡 ── Debian 系统和 TeslaBox 程序
```

约束如下：

- TF 卡只承担 Debian 系统和程序运行，不存放 TeslaCam 虚拟磁盘、录像快照或媒体索引。
- 数据盘是录像数据介质，可以是 U 盘、USB SSD、USB 硬盘或在 M.2 接口上的 NVMe；当前实机使用 128GB U 盘。
- 当 Debian 仍运行在 TF 卡时，M.2 NVMe 可以作为 TeslaBox 数据盘；系统盘不允许被列为初始化候选或作为数据盘格式化。
- 外接数据盘必须视为设备固定组成部分。车辆录像期间拔出数据盘属于故障，不是正常操作。

## 存储模型

外接 U 盘不是以现有 TeslaCam 分区直接透传给车辆，而是作为 Linux 管理的数据盘：

```text
外接 128GB U 盘
└── 支持 reflink 的 Linux 文件系统
    ├── images/
    │   └── teslacam.img
    ├── snapshots/
    ├── index/
    └── state/
```

`teslacam.img` 内部使用 Tesla 可识别的文件系统和目录结构。USB Gadget 把该镜像暴露给车辆，车辆写入的数据最终仍保存在外接 U 盘上。

必须满足以下规则：

- 初始化数据盘可能涉及重新分区或格式化，必须由用户显式确认，服务启动时不得自动执行。
- 初始化前必须提示用户备份原 U 盘中的录像。
- 虚拟磁盘容量必须为快照写时复制和运行状态预留空间，不能占满整个物理数据盘。
- 设置中心创建的虚拟磁盘应尽可能利用物理容量，同时至少预留物理盘的 5% 且不少于 10GB；运行时快照和导出仍必须遵守 8GiB 与 5% 的可用空间红线。受 MBR 寻址边界限制，车机可见镜像最大为 2TB。
- 用户可以选择单一 exFAT TeslaCam 分区，或选择 exFAT TeslaCam 加 FAT32 MUSIC 双分区，并调整两者比例；页面必须在擦除前展示预计容量。
- 在已确认的目标车机上，exFAT 分区根目录可并存 `TeslaCam/`、`Wraps/`、`Boombox/` 和 `LightShow/`；MUSIC 文件写入可选的 FAT32 分区根目录。TeslaBox 不以未在目标车机复验的通用目录限制覆盖这一实车结论。
- 媒体中心上传必须先写入数据盘内的受控暂存区，上传本身不触碰车机虚拟盘。默认由用户确认 OTG 已物理断开后，系统才可暂停 Gadget、回收快照、以 loop 方式短暂读写相应分区并重新卸载；用户明确开启自动维护恢复时，系统可代为解绑并在完成后安排温重启。同一 `boot_id` 内不得重新绑定 UDC，必须通过温重启或冷启动恢复。
- 每个已保存 WiFi 必须可以独立选择 DHCP 或静态 IPv4（地址、子网掩码、网关和 IPv4 DNS）。配置只绑定该 NetworkManager 连接 UUID；切换到另一个 WiFi 或更换无线接口名称时不得串用地址配置。
- 媒体中心必须提供锁车音效、喷漆车间皮肤、自定义灯光秀和音乐的列表、删除和必要预览。锁车音效和皮肤保留预览副本；音乐只展示清单，避免重复占用数据盘空间。
- 媒体中心刷新时必须从只读 TeslaCam 快照扫描车机或电脑直接写入的媒体；这些文件标记为“直接写入”，不得把未受 TeslaBox 管理的文件误认为可安全删除的暂存资源。
- 页面必须分别展示车机 exFAT 虚拟盘可用空间和承载镜像的外层 XFS 可用空间；普通刷新只能重新读取容量，不得为了改变外层数值而隐式断开 Gadget。
- 网页删除应在内核支持时通过 discard 返还 file-backed loop 的外层空间。录像删除、历史空间回收和媒体维护必须统一使用 TeslaBox 媒体运行时内置的 exfatprogs 1.2.0，不得回退到系统旧版 `fsck.exfat`。历史删除空间只能在 Gadget、快照和 loop 均已释放的独占维护窗口内，根据检查后的 Allocation Bitmap 回收；不得根据文件内容猜测空闲区域，也不得对仍在使用的镜像直接执行整文件打洞。
- 正在向车辆暴露的可写镜像不得被 Linux 直接挂载。
- 媒体索引、快照和高频运行状态应写入外接数据盘，避免增加 TF 卡写入压力。
- 数据盘、镜像、快照和挂载点必须通过稳定标识识别，不能依赖可能变化的 `/dev/sdX` 名称。
- 系统盘必须保存数据盘身份登记册。只有完整完成分区、XFS、目录、TeslaCam 镜像和只读校验后，设备才可登记为活动数据盘。
- 未初始化设备不得自动格式化。设置中心可以提供显式初始化和重新初始化，但必须只列出带 `/dev/disk/by-id/` 稳定身份和稳定序列号的非系统整盘，并要求用户物理拔掉 OTG、再次输入序列号和勾选擦除确认。
- 初始化中断或设备被拔出时必须保留可恢复记录；用户可以重新插入继续，也可以放弃任务并恢复原活动设备选择。

虚拟磁盘容量、文件系统格式、卷标、快照周期和保留数量属于部署参数，在板端和实车测试后确定默认值。

## USB Gadget

TeslaBox 必须通过 configfs 管理 USB Mass Storage Gadget：

- 启动前验证 UDC、configfs 和 mass-storage function 可用。
- Gadget 的 backing file 指向 `teslacam.img`，不指向已经由 Linux 挂载的文件系统。
- Mass Storage LUN 默认设置 `nofua=1`，以避免 Windows 对可移动盘的高频 FUA 小块同步将写入吞吐压低。该策略优先连续写入性能；异常断电或强拔线时，最后少量尚未落盘的数据可能丢失，用户应等待写入结束并安全断开。
- 服务启动时必须把 Linux 脏页写回阈值固定为后台 64MiB、最大 256MiB，避免 2GB 板子按比例累积约 1GB 脏页后产生数秒的写入归零；阈值写入失败只记录告警，不得阻止车机存储主链路启动。
- 绑定和解绑操作必须幂等；同一系统开机周期的服务重启只能检查或停止既有 Gadget，不得重新绑定 UDC。
- 未连接数据盘时 Debian 必须仍能正常启动并进入 `WAITING_FOR_DATA_DRIVE`，不得暴露空 LUN，也不得因等待设备无限阻塞启动。
- 已初始化且稳定标识匹配的数据盘在开机后插入时，系统必须自动挂载并重新检查 backing image；如果本次开机的安全绑定窗口已经结束，则保持 Gadget 解绑并提示用户插好 OTG 后执行温重启恢复；完全断电预插 OTG 的冷启动作为温重启失败时的兜底。该流程不得自动格式化未知或未初始化的磁盘。
- backing image 未准备好或数据盘掉线时，不得向车辆暴露一个不可写或错误的磁盘。
- Gadget 工作期间数据盘异常掉线时，应立即进入故障状态，尽最大可能解绑 UDC、停止继续提供 LUN 并发出明确告警，避免扩大文件系统损坏；数据盘恢复后必须重新完成身份、挂载和镜像检查，不能直接复用旧状态。
- 数据盘掉线时必须回收旧快照、只读挂载和 loop 设备；同一数据盘重新插入后仍需重新完成身份和 backing image 校验。
- ROCK 3A 每个 `boot_id` 最多允许一次 UDC 绑定尝试。该尝试必须位于内核启动后的 60 秒和服务首次启动收敛阶段；无法确认系统启动时长时禁止新绑定，但不得拆除已经绑定的 Gadget。若主机在限定时间内未完成枚举，必须立即解绑，本次开机不得因轮询、udev、服务重启或页面操作再次绑定。
- 已绑定 Gadget 的一次 `lsblk`、configfs 或 UDC 只读检查超时不得被解释为数据盘掉线，也不得触发 UDC 解绑。
- 已完成启动绑定的 Gadget 在车机复位或重新枚举期间必须保持绑定；只有确认 backing store 不可用或活动数据盘真实掉线时才停止 LUN。

## 一致性快照和在线查看

在线查看必须从一致性快照读取：

```text
车辆持续写入 teslacam.img
             │
             ├── 创建写时复制快照
             ▼
       snapshot.img
             │
             ├── 检查或修复快照中的文件系统
             ├── 只读挂载
             ├── 扫描 TeslaCam 和 TeslaTrackMode
             └── 提供列表、播放和下载 API
```

必须满足以下规则：

- 创建和读取快照不得解绑正在工作的 Gadget。
- 快照必须独立于仍在写入的原始镜像。
- 快照只能只读挂载，修复操作只能作用于快照副本。
- 快照应先尝试直接只读挂载；只有副本无法挂载，或遍历快照时明确返回文件系统 `EIO`，才允许对新建快照副本运行一次 `fsck.exfat` 并重试一次扫描，不得用高频全盘检查干扰车端音乐读取或录像写入。
- 对已执行文件系统修复的快照，后台自动重扫至少冷却 5 分钟；用户显式触发的手动扫描不受此限制。
- API 只能返回快照中已经完整可读的媒体文件。
- 新快照可用后应原子切换媒体索引，正在播放的旧快照不能被提前删除。
- 快照失败不得中断车辆录像；系统应保留最后一个可用快照并报告降级状态。
- 快照必须有空间上限和回收策略，不能耗尽外接数据盘。

## TeslaCam 功能范围

第一阶段支持：

- `RecentClips`
- `SavedClips`
- `SentryClips`
- `TeslaTrackMode`
- 按日期、事件和摄像头查询
- 单路 MP4 播放和下载
- 存储、Gadget、快照和索引状态查询

后续阶段支持：

- 多摄像头同步播放
- 视频缩略图
- 时间轴和事件展示
- NAS 自动备份
- 锁车提示音、灯光秀和其他 Tesla USB 资源管理

## 状态机

核心服务至少需要表达以下状态：

```text
STARTING
  ↓
WAITING_FOR_DATA_DRIVE
  ↓
PREPARING_BACKING_STORE
  ↓
GADGET_ACTIVE
  ├── SNAPSHOT_CREATING
  ├── SNAPSHOT_READY
  └── DEGRADED

任意状态 ── 严重存储故障 ──> FAULT
```

状态变化必须可通过日志和 API 查询。服务退出、重启、重复 udev 事件和异常断电后，状态机应能够重新收敛，不得重复格式化、重复创建 Gadget 或留下可写挂载。

数据盘热插拔必须触发状态收敛：缺盘启动保持 `WAITING_FOR_DATA_DRIVE`；匹配的数据盘插入后自动挂载并验证 backing store，但只有新的冷启动绑定窗口才能进入 `GADGET_ACTIVE`；活动数据盘掉线后进入 `FAULT` 并停止暴露 LUN。

## 安全边界

- 禁止同时把同一个可写文件系统交给 Tesla 和 Linux 挂载。
- 禁止服务启动时隐式格式化数据盘、修改分区或删除录像。
- 所有破坏性初始化操作必须显示目标磁盘的稳定标识、容量和型号，并要求单独执行。
- 设置中心只开放受登录和同源校验保护的存储初始化接口；不得开放任意设备路径、静默格式化或录像删除能力。
- ROCK 3A 的部分 5.10 内核在物理拔掉 OTG 后仍会保留 UDC 的 `configured` 和 `high-speed`，因此这些值只能表示最近一次枚举完成，不能单独证明当前仍有物理连接。
- 当 UDC 保留 `configured`、但 `/sys/class/udc/<UDC>/device/gadget/suspended` 为 `1` 时，页面必须显示“可能已断开”，并说明主机正常休眠和物理拔线在该内核上无法无损区分；不得继续显示为活动连接，也不得为确认状态而自动重绑并中断车辆写入。
- 在线更新默认自动安全解绑 TeslaBox 自己的 Gadget，暂停状态必须保存在 TF 系统盘并跨服务重启和程序更新保持；新程序健康检查通过后自动温重启恢复。媒体变更仍默认要求用户确认物理 OTG 已拔出，只有用户明确开启“媒体自动维护恢复”才可代为解绑。这些便利模式不能替代物理断线确认的最高安全性。用户先插入 OTG 线后只能预约下一次启动恢复，本次运行不得立即绑定；温重启用于进入新的 `boot_id`，完全断电冷启动作为兜底。接口不得接受任意 Gadget 名称，更新失败时也不得运行时自动重绑。
- `/sys/class/extcon/extcon0/state` 在实测中无法区分板载供电状态与设备模式 OTG 物理连接，OTG 已拔时仍可能为 `USB=1`，不得将其用于绑定授权。
- 数据盘空间不足、只读、I/O 错误和掉线必须明确告警。

## 第一阶段验收条件

第一阶段完成必须同时满足：

1. ROCK 3A 使用 TF 卡启动 Debian，TeslaCam 数据不写入 TF 卡。
2. 非系统数据盘（外接 U 盘或 M.2 NVMe）完成显式初始化并保存虚拟磁盘镜像。
3. ROCK 3A 通过 OTG 向测试主机或 Tesla 稳定暴露 USB Mass Storage。
4. 主机写入虚拟盘时，TeslaBox 可以创建并只读挂载快照。
5. 网页或 API 可以播放快照中已经完成的 MP4，同时 Gadget 保持连接和可写。
6. 服务重启后可以恢复快照和索引状态，但不会在相同 `boot_id` 下重新绑定 Gadget。
7. 外接数据盘掉线、空间不足和快照失败时不会自动格式化或静默损坏数据。
8. 缺盘启动不会阻塞 Debian；开机后插入已初始化数据盘可自动挂载和校验，但恢复 Gadget 必须预插 OTG 后进入新的 `boot_id`，优先温重启，失败时冷启动兜底。
9. Gadget 活动期间拔出数据盘会被检测并停止暴露 LUN，同时通过日志和 API 报告故障。
10. 未登记的非系统存储在页面中明确显示为未初始化，必须经过序列号和擦除双重确认才可初始化；中断后可以继续或取消。

## 不在第一阶段范围内

- 播放当前仍在写入的 MP4。
- 摄像头秒级实时直播。
- 自动迁移现有 U 盘录像后再格式化原盘。
- 对无稳定 `/dev/disk/by-id/` 身份、无稳定序列号、系统盘、正在挂载、作为 swap 使用或容量不足的设备执行网页初始化。
- NAS、云端或中继模式下的低码率转码。
