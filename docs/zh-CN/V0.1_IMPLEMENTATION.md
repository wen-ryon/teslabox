# V0.1 实现现状与迁移说明

## 最终需求边界

V0.1 的最终目标是 [TeslaUSB 模拟模式](TESLAUSB_REQUIREMENTS.md)：TF 卡只运行 Debian；外接 128GB U 盘保存虚拟磁盘、快照和媒体索引；ROCK 3A 通过 OTG 向 Tesla 模拟 USB Mass Storage。

初版“直接挂载物理 Tesla U 盘”的主流程已经被移除。仓库保留了可复用的 TeslaCam 解析器、HTTP API、配置、系统命令边界和测试，并已切换到最终架构的生命周期状态机。数据盘显式初始化、XFS reflink backing store、TeslaCam 虚拟磁盘镜像、自动挂载、Gadget 管理、断电重启恢复、掉盘保护、reflink 快照和只读媒体读取链路已经实现；板端快照和播放已经验收，仍需完成 Tesla 持续写入时的实车并行验收。

## 当前实现范围

当前代码完成以下闭环：

1. 按 UUID 或卷标发现唯一的外接数据分区，UUID 配置后不回退到卷标。
2. 只自动挂载身份匹配、已初始化为 XFS 的数据盘；不格式化、不修复，也不创建 backing store 或镜像。
3. 检查 configfs 和 UDC 后，幂等创建、绑定或解绑 TeslaBox 专属 Gadget。
4. 通过状态机和 `/api/v1/storage` 暴露等待数据盘、准备、Gadget 活动、降级和故障状态，以及 UDC 枚举状态和速率；不再把残留的 `configured` 误报为当前物理连接。
5. 从当前可用的只读快照解析 `TeslaCam` 和 `TeslaTrackMode`，并通过视频列表 API 发布索引。
6. 使用三秒低频轮询收敛数据盘状态；不再从 udev 向 Go 主进程发送信号，避免启动阶段信号竞态破坏 Gadget 绑定窗口。
7. 通过独立的 `teslabox-init` 工具核对非系统数据整盘的稳定路径、序列号、容量和占用状态，再显式创建 GPT、XFS reflink 文件系统和 backing store 目录。
8. 通过独立的 `teslabox-image-init` 工具创建预留快照空间的 MBR、exFAT TeslaCam 稀疏虚拟磁盘镜像。
9. 通过独立的 `teslabox-gadget` 工具检查 UDC 占用，幂等创建、绑定和解绑 configfs USB Mass Storage Gadget。
10. 缺盘启动时保持等待；数据盘晚到后自动挂载并检查镜像，但 Gadget 仅在新的冷启动窗口恢复；活动数据盘掉线时尽最大可能停止 LUN 并保持故障状态，数据盘恢复后自动重新收敛。
11. 媒体浏览按需对原始镜像执行 XFS reflink 克隆，优先直接以只读 loop 挂载；只有副本无法挂载时才对第一个 exFAT 分区运行 `fsck.exfat -p` 后重试，避免周期性全盘检查干扰车端读写。
12. 新快照扫描成功后原子替换视频索引；失败时保留最后一个可用快照并进入降级状态。
13. 视频内容和下载接口使用 `http.ServeContent` 提供 HTTP Range，不直接读取仍在向 Tesla 暴露的原始镜像。
14. 首次创建快照前，只卸载和解绑 backing path、文件名及目录均属于 TeslaBox 的遗留资源；不会清理系统中的其他 loop 设备。
15. 数据盘低于字节或百分比门槛时停止创建新快照，优先保留 Gadget、车端录像和最后一个可用媒体快照；空间紧张时先回收已退役快照。
16. 自动快照连续失败时按扫描间隔指数退避并设置最大间隔，API 状态同时暴露失败次数、下次重试时间和容量信息；手动扫描仍可用于诊断和恢复确认。
17. TF 系统盘使用原子 JSON 登记册保存活动数据盘 UUID、序列号、型号、容量和初始化进度；活动设备选择不依赖 `/dev/sdX`。
18. 设置中心枚举具有稳定 by-id 身份的 USB 整盘和非系统 NVMe 数据整盘，经过序列号复核和擦除确认后复用现有初始化器创建 GPT/XFS、目录和 TeslaCam 镜像。
19. 初始化意图在修改磁盘前落盘；失败或断电后可继续，目标设备被拔出时仍可取消任务并恢复原活动数据盘。
20. 活动数据盘掉线时停止 Gadget，并回收当前和退役快照、只读挂载及 loop 状态；重新插入后从身份、挂载和镜像检查重新收敛。
21. ROCK 3A 使用系统 `boot_id` 限制每次系统启动最多进行一次 UDC 绑定尝试；未完成枚举时自动解绑，同一开机周期的轮询、udev、服务重启和页面操作均不能再次绑定。人工安全断开后只允许预约下一次启动恢复，可由温重启进入新的 `boot_id`，冷启动作为兜底。
22. 媒体中心提供锁车音效、喷漆车间皮肤、自定义灯光秀和音乐的上传、列表、删除与必要预览；文件先写入外接数据盘的受控暂存区，不直接挂载车机正在写入的原始镜像。
23. 应用媒体变更默认要求用户确认 OTG 已物理断开；用户可在设置中心明确开启“媒体自动维护恢复”，让系统代为安全解绑、写入并预约温重启。在线更新则默认自动执行同样的安全断开、健康检查和系统重启恢复；两类策略分别保存，避免一次设置改变媒体写入的默认安全边界。
24. 每个已保存 WiFi 连接可独立选择 DHCP 或静态 IPv4。静态模式校验 IPv4 地址、连续子网掩码、同网段网关和最多四个 IPv4 DNS；配置写入 NetworkManager 连接 UUID，不依赖接口是否叫作 `wlan0`，下次连接同一网络时自动生效。
25. WiFi 和 AP 接口默认从 NetworkManager 动态发现；AP 启动优先跟随已连接上游的信道，否则选择当前网卡与监管域允许的信道。没有无线网卡或驱动不支持 AP 时只降级无线管理，不影响 TeslaUSB、媒体和有线管理。

`teslabox` 启动和自动恢复路径不会格式化、分区、创建目录或创建镜像。只有用户在已认证设置中心完成目标序列号和擦除双重确认后，主进程才调用同一套受检初始化器；正常运行只自动挂载登记且身份匹配的数据盘，并统一管理 Gadget 生命周期。`teslabox-gadget` 命令和对应的 oneshot 单元只保留给人工诊断或兼容迁移，不应与主服务同时常驻管理同一个 UDC。

## 对 TeslaUSB 的借鉴

TeslaBox 参考了 [marcone/teslausb](https://github.com/marcone/teslausb) 的以下设计原则：

- 设备暴露、挂载、修复和归档必须有明确状态边界。
- 所有连接和断开操作必须幂等，允许服务在异常断电后重新收敛。
- 车端正在使用的 backing file 不能同时由 Linux 直接读写。
- 需要在线查看车端写入内容时，应读取一致性快照，而不是挂载正在导出的文件系统。
- `RecentClips`、`SavedClips`、`SentryClips` 和 `TeslaTrackMode` 应统一建立媒体索引。

ROCK 3A 的 USB Gadget 硬件可行性已经由用户确认。本项目采用支持一致性快照的方案：车辆持续写入原始镜像，TeslaBox 对快照副本执行检查、只读挂载和媒体扫描。正常在线查看不应断开车辆端 Gadget。

## 配置

配置样例位于 `configs/teslabox.env.example`。

关键配置：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `TESLABOX_HTTP_ADDR` | `:80` | HTTP 监听地址；官方 systemd 服务以 root 运行，可绑定低位端口 |
| `TESLABOX_WEB_AUTH_STATE` | `/var/lib/teslabox-system/web-auth.json` | TF 系统盘上的认证状态；权限为 `0600`，保存带盐慢哈希、会话密钥和改密代次 |
| `TESLABOX_MAINTENANCE_STATE` | `/var/lib/teslabox-system/maintenance.json` | TF 系统盘上的维护策略；媒体自动维护默认关闭，在线更新自动断开并重启恢复默认开启 |
| `TESLABOX_TESLA_TIME_ZONE` | `Asia/Shanghai` | Tesla 文件名与无时区 `event.json` 时间戳按车辆所在地时区解析，不依赖板子系统时区 |
| `TESLABOX_WEB_PASSWORD_SHA256` | 空 | 仅兼容旧部署的 SHA-256 密码摘要；首次页面改密后迁移到认证状态文件 |
| `TESLABOX_WEB_SESSION_SECRET` | 空 | 仅兼容旧部署的 HMAC 密钥；必须与旧密码摘要同时配置 |
| `TESLABOX_WEB_SESSION_TTL` | `168h` | 登录会话有效期，最大 365 天 |
| `TESLABOX_DATA_UUID` | 空 | 数据分区文件系统 UUID，设置后优先且不回退卷标 |
| `TESLABOX_DATA_LABEL` | `TESLABOX` | 未配置 UUID 时使用的数据分区卷标（XFS 最多 12 个字符） |
| `TESLABOX_DATA_MOUNT_PATH` | `/var/lib/teslabox` | 期望的数据盘挂载点 |
| `TESLABOX_IMAGE_PATH` | `images/teslacam.img` | 数据盘内的虚拟磁盘相对路径 |
| `TESLABOX_SNAPSHOT_PATH` | `snapshots` | 数据盘内的快照相对路径 |
| `TESLABOX_SNAPSHOT_MOUNT_PATH` | `/run/teslabox/snapshots` | 快照只读 loop 挂载根目录 |
| `TESLABOX_INDEX_PATH` | `index` | 数据盘内的媒体索引相对路径 |
| `TESLABOX_STATE_PATH` | `state` | 数据盘内的高频运行状态相对路径 |
| `TESLABOX_STORAGE_REGISTRY` | `/var/lib/teslabox-system/storage-registry.json` | TF 系统盘上的活动数据盘身份和初始化进度登记册 |
| `TESLABOX_CONFIGFS_PATH` | `/sys/kernel/config/usb_gadget` | USB Gadget configfs 路径 |
| `TESLABOX_UDC_PATH` | `/sys/class/udc` | UDC 类目录 |
| `TESLABOX_UDC_NAME` | 空 | 可选的固定 UDC 名称；为空时要求系统中只有一个 UDC |
| `TESLABOX_GADGET_NAME` | `teslabox` | TeslaBox 专属 Gadget 名称 |
| `TESLABOX_GADGET_SERIAL` | `TESLABOX-071C4AAFBA8BEB80` | 向 USB 主机暴露的稳定序列号 |
| `TESLABOX_RELEASE_GADGET` | `radxa-otgutils` | 唯一允许在启动时临时解绑的同名冲突 Gadget |
| `TESLABOX_BOOT_ID_PATH` | `/proc/sys/kernel/random/boot_id` | 区分真正的系统冷启动和同一开机周期内的服务重启 |
| `TESLABOX_BOOT_UPTIME_PATH` | `/proc/uptime` | 将新 UDC 绑定限制在内核启动后的 60 秒安全窗口内；读取失败时禁止新绑定 |
| `TESLABOX_GADGET_PAUSE_STATE` | `/var/lib/teslabox-system/gadget-paused` | 记录当前 boot_id 的服务所有权、绑定尝试、人工暂停和下一次启动恢复预约 |
| `TESLABOX_WIFI_INTERFACE` | 空 | 可选的上游无线接口名；为空时从 NetworkManager 自动发现非热点 WiFi 设备 |
| `TESLABOX_AP_INTERFACE` | `ap0` | 热点虚拟接口兜底名称；活动连接或连接配置中的实际接口优先 |
| `TESLABOX_SCAN_INTERVAL` | `30s` | 用户进入录像浏览后的媒体重扫间隔 |
| `TESLABOX_SNAPSHOT_IDLE_INTERVAL` | `5m` | 无人浏览录像时的低功耗快照间隔；首次启动和重新进入录像页仍会立即刷新 |
| `TESLABOX_SNAPSHOT_ACTIVE_WINDOW` | `2m` | 录像浏览激活后保持高频快照的时长 |
| `TESLABOX_POLL_INTERVAL` | `3s` | 设备轮询间隔 |
| `TESLABOX_SNAPSHOT_TIMEOUT` | `2m` | 单次快照复制、检查、挂载和扫描的最长时间 |
| `TESLABOX_SNAPSHOT_RETRY_MAX` | `10m` | 自动快照连续失败时指数退避的最大间隔 |
| `TESLABOX_MIN_FREE_BYTES` | `8589934592` | 创建新快照时应为车端录像保留的最小可用字节数 |
| `TESLABOX_MIN_FREE_PERCENT` | `5` | 创建新快照所需的最小可用空间百分比 |

服务不接受 `/dev/sdX` 作为持久配置。推荐初始化后记录 UUID；卷标重复时服务会进入故障状态，不会猜测目标磁盘。破坏性初始化参数不会放入常驻服务的自动启动路径。

快照运行依赖 `cp`、`losetup`、`fsck.exfat`、`mount` 和 `umount`。当前 ROCK 3A 定制内核没有 exFAT 内核模块，因此还需要 Debian 的 `exfat-fuse`；代码只在内核报告不支持 exFAT 时回退到 `mount.exfat-fuse`。

## Web 管理页面

浏览器打开 `http://<TeslaBox-IP>/` 即可查看 USB Gadget、互联网连通性、设备温度、CPU、内存、系统盘、数据盘、快照和录像状态，并按录像类型、日期或事件筛选、播放和下载当前只读快照中的视频。系统状态通过读取 procfs、sysfs 和文件系统统计信息采集，不执行外部命令；互联网连通性使用短时缓存，避免页面轮询频繁建立外部连接。录像列表可按月、滚动七日周期或日组织为纵向时间线，只在视角不完整时显示警告，并将 `event.json` 中的地点展示在录像时长旁；页面使用纯黑背景，并提供蓝、绿、红三种强调色。页面资源编译在 `teslabox` 二进制中，不依赖公网或外部 CDN。

时刻分组使用录像类型和事件目录划定边界，同组最早与最晚文件时间最多相差 2 秒，并禁止同一摄像头重复进入同组，因此不会把相邻录像片段链式合并。服务读取每个 MP4 的 `mvhd` 元数据获取真实时长，再将间隔不超过 5 秒的分钟片段合并为完整录像会话。

播放器将前视、后视、左右翼子板和左右 B 柱六路画面组合在同一个播放窗口中，并共用一条会话时间轴和一套播放控制。自动画质在多路布局下默认使用板端标准画质合成，浏览器只解码一路，避免部分终端同时解码六路原画时达到硬件解码上限；单路布局继续默认使用原画。用户显式选择原画时，浏览器仍会分别加载布局需要的原生视频，并用文件名时间补偿各路最多 2 秒的起始偏差。

异步导出复用播放器的六路、四路 A、四路 B、三路和单路视角定义，不再允许任意摄像头组合产生不可预测布局。剪辑视频默认提供 30 FPS 高保真合成，单路额外提供源分辨率原画；跨分钟片段按绝对时间对齐并输出一条完整 MP4。多路需要原画时，按完整分钟下载未转码 MP4 和离线同步浏览页，而不是在 ROCK 3A 上把六路重新编码成一条伪原画 MP4。

扫描器同时读取事件目录中的 `event.json`。录像文件名和没有时区后缀的事件时间戳均按 `TESLABOX_TESLA_TIME_ZONE` 解释；默认 `Asia/Shanghai`，避免板子若运行 UTC 时被浏览器二次换算为晚八小时。录像卡片展示车辆记录的触发时间、城市、街道、近似经纬度、触发原因和可识别的关联摄像头；列表时间轴和播放器时间轴按 `timestamp - 会话开始时间` 绘制红色事件点，点击后跳转到对应的全局时刻。缺失、损坏或时间超出录像范围的事件元数据不会阻断 MP4 扫描，也不会伪造时间轴位置。

Web 认证为单用户模式，并且始终启用。全新安装第一次启动时会创建权限为 `0600` 的认证状态文件，初始密码为 `teslabox`。登录后页面会强制要求修改默认密码；完成前，除登录、注销、会话状态和修改密码外，其余管理与录像 API 均返回 `428 Precondition Required`。

新密码长度为 8～128 个 UTF-8 字节，使用随机盐和 PBKDF2-HMAC-SHA256 慢哈希保存，不记录明文。修改成功会同时轮换随机会话密钥并增加凭据代次，使其他浏览器持有的旧 Cookie 立即失效。设置中心“安全与账户”可随时再次修改密码。

已有部署仍可继续使用原来的环境变量：

```bash
printf '%s' '你的管理密码' | sha256sum
openssl rand -hex 32
```

将第一条命令的摘要写入 `TESLABOX_WEB_PASSWORD_SHA256`，第二条命令的随机值写入 `TESLABOX_WEB_SESSION_SECRET`。旧配置不会在升级时被重置为默认密码；用户使用旧密码登录并完成一次页面改密后，服务会原子写入新认证状态并在后续启动时优先使用它。会话 Cookie 使用 HMAC 签名、HttpOnly 和 SameSite=Strict；普通 HTTP 局域网仍不具备 TLS 传输加密能力，不应复用其他账户密码。全新设备应在可信的本地网络中尽快完成首次改密，避免默认密码暴露窗口。

## 数据盘初始化

设置中心“外接存储”区域提供同等安全边界的图形化入口。页面只显示有稳定 USB by-id 和序列号的整盘；服务端再次核实传输类型、容量、挂载和 swap 状态。初始化会先在 TF 系统盘写入待处理记录，完成 XFS、目录、TeslaCam 镜像只读校验和设备标记后才切换活动 UUID。失败、断电或拔盘不会把半成品当作可用数据盘。已登记且只挂载在 TeslaBox 数据目录的活动盘允许显式“重新初始化”，但仍会要求物理拔掉 OTG、重新输入序列号并确认清空全部数据。

初始化工具默认只输出计划，不会修改磁盘。`--device` 只接受 `/dev/disk/by-id/usb-*` 整盘稳定路径，`--confirm-serial` 必须与内核读取的整盘序列号完全一致；已挂载、swap、非 USB、非整盘或容量异常的设备都会被拒绝。

```bash
teslabox-init \
  --device /dev/disk/by-id/usb-_TESLADRIVE_071C4AAFBA8BEB80-0:0 \
  --confirm-serial 071C4AAFBA8BEB80
```

核对 dry-run 输出后，只有增加 `--execute` 并以 root 身份运行才会擦除磁盘。工具创建单一 GPT 分区、卷标为 `TESLABOX` 的 XFS 文件系统和 `images`、`snapshots`、`index`、`state` 目录。XFS 卷标最长为 12 字节，因此不能使用 13 字节的 `TESLABOX_DATA` 作为卷标。

## TeslaCam 镜像初始化

`teslabox-image-init` 默认只预演。设置中心不再把镜像上限固定为 96GB，而是使用 `min(物理容量 - max(20GB, 物理容量的 5%), 2TB)` 并向下按 1GB 对齐；例如 128GB 盘预计提供 108GB，500GB 盘预计提供 475GB。预留空间用于 reflink 快照、导出、索引和文件系统运行开销，不能作为车机可写容量使用。

默认布局使用 MBR 分区表、从 1MiB 开始的单一 exFAT 分区、`TESLACAM` 卷标和 `TeslaCam` 根目录。用户也可以在初始化页面勾选 MUSIC 音乐分区并按 10% 到 95% 调整 TeslaCam 比例；此时第一分区为 exFAT/TESLACAM，第二分区为 FAT32/MUSIC。TeslaCam 分区至少保留 32GB，音乐分区至少保留 1GB。分区选择会擦除整块外接盘，且 FAT32 音乐分区仍需以目标车型和车机固件实测兼容性。

工具要求 backing store 为独立挂载的 XFS 且 `reflink=1`，拒绝覆盖已有镜像，并强制为快照预留至少 16GB 物理容量。命令行可以通过 `--music --teslacam-percent 80 --music-label MUSIC` 预演双分区布局。

```bash
teslabox-image-init
sudo teslabox-image-init --execute
```

原厂 5.10 内核没有可用的内核态 exFAT 挂载驱动，因此初始化工具使用 `/sbin/mount.exfat-fuse` 临时挂载新镜像并创建目录。镜像交给 USB Mass Storage Gadget 后不会同时挂载到 Linux。

初始化开始前，主状态机会先暂停并解绑 Gadget、回收未被播放或导出占用的快照、卸载 XFS 数据盘，然后独占存储维护窗口。初始化完成后不会在同一个 `boot_id` 内重新绑定 UDC；用户物理插好 OTG 后可在日志中心执行“温重启恢复”，程序保存下一次启动恢复标记并提交系统重启。若温重启后仍无法枚举，才使用完全断电后预插 OTG 的冷启动作为硬件兜底。

## USB Mass Storage Gadget

`teslabox-gadget` 默认只输出状态。`--action start` 和 `--action stop` 在没有 `--execute` 时也只做 dry-run；真实修改 configfs 必须以 root 身份显式增加 `--execute`。

```bash
teslabox-gadget --action status
teslabox-gadget --action start
sudo teslabox-gadget --action start --execute
sudo teslabox-gadget --action stop --execute
```

启动前会拒绝以下情况：TeslaCam 镜像缺失、镜像是符号链接或非普通文件、镜像仍被 loop 设备使用、UDC 不唯一或目标 UDC 已被其他 Gadget 占用。配置顺序固定为先写 USB 身份和 LUN 属性、最后写 backing file、创建 function 链接并绑定 UDC。停止只删除名为 `teslabox` 的 Gadget，不会接管或删除板载 `radxa-otgutils` 配置。

板端重启后 configfs 会清空，Radxa 的 `radxa-adbd.service`、`radxa-usbnet.service` 可能在 TeslaBox 之后延迟初始化 `radxa-otgutils`。首装脚本和主程序只针对这两个固定服务执行停用与屏蔽，systemd unit 同时声明冲突关系，避免原厂 FunctionFS 请求污染 DWC3 的 EP0 状态。`teslabox.service` 仍会在进程初始化早期释放完全同名的遗留 Gadget，并保留至少 500 毫秒的稳定断线窗口；数据盘和镜像就绪后，主状态机再绑定 TeslaBox。常规收敛通过 `TESLABOX_RELEASE_GADGET=radxa-otgutils` 限制可接管名称，不删除原厂配置。主服务停止时会有序解绑 TeslaBox Gadget。`teslabox-gadget.service` 没有安装目标，只用于人工兼容操作。

日志中心读取 UDC 的 `configured`、速率和 composite Gadget 的 `suspended` 状态。`configured` 且未挂起时显示“已完成枚举”；`configured` 且 `suspended=1` 时显示“可能已断开”，因为该内核会在拔线后残留 `configured/high-speed`，而 USB 主机正常休眠也会产生相同状态，软件无法在不中断车机存储的前提下无损区分。板端实测还证明 extcon 在 OTG 已拔时仍可能报告 `USB=1`，不能作为物理插线凭据。状态文件结合系统 `boot_id` 保证每次开机最多一次绑定尝试；未及时枚举就自动解绑。媒体手动维护和人工安全断开后，用户需先插好 OTG，再在日志中心预约下一次启动恢复；默认在线更新会自行完成安全断开、健康检查和系统重启，本次运行始终不运行时重绑。

数据盘状态由三秒低频轮询收敛。旧版通过 udev 向主进程发送 `SIGUSR1`，真实设备日志证明块设备事件可能早于 Go 信号订阅并终止刚启动的服务，因此规则已改为无动作兼容文件；首装或完整系统文件升级后需重新加载 udev 规则。

## API

### 健康检查

```http
GET /healthz
```

### USB 与索引状态

```http
GET /api/v1/storage
```

### 视频列表

```http
GET /api/v1/videos
```

支持以下查询参数：

- `clip_type=recent|saved|sentry|track`
- `camera=front|back|left_repeater|right_repeater`
- `date=2026-07-15`
- `event=事件目录名`
- `limit=1..1000`
- `offset=0..N`

### 视频播放与下载

```http
GET /api/v1/videos/{id}/content
GET /api/v1/videos/{id}/download
```

两个接口都支持 HTTP Range；播放接口返回 `video/mp4`，下载接口额外返回附件文件名。文件只从当前已发布的只读快照打开。

### Rockchip 媒体能力与录像技术元数据

```http
GET /api/v1/media/capabilities
GET /api/v1/videos/{id}/metadata
```

能力接口从实际安装的 FFmpeg 读取 MPP 编解码器、RGA 滤镜和硬件加速状态。元数据接口按视频 ID 定位当前只读快照中的文件，并通过 ffprobe 返回 codec、分辨率、像素格式、帧率、time base、起始 PTS、时长和码率等有限字段。客户端不能提交文件路径，外部进程继承请求取消信号并受 `TESLABOX_MEDIA_PROBE_TIMEOUT` 限制。

### 六路录像时刻分组

```http
GET /api/v1/video-groups
```

查询参数与视频列表一致。响应按最多 2 秒的时间偏差合并同一录像类型、同一事件中的不同摄像头，并返回组内视频、完整性、总大小和实际时间跨度。摄像头条件用于筛选“包含该视角的分组”，不会从返回分组中删除其他视角。

### 完整录像会话

```http
GET /api/v1/video-sessions
```

列表响应将连续的分钟时刻组组合成完整录像段，并返回用于月、周、日归档的摘要、`thumbnail_url` 以及可用的 `event_metadata`；`GET /api/v1/video-sessions/{id}` 返回指定录像段的完整分钟明细。页面据此实现跨文件续播、统一拖动进度、事件点跳转、六路同窗合成和单视角切换。

扫描器会索引录像目录内由 Tesla 生成的 `thumb.png`。缩略图通过受保护的 `GET /api/v1/thumbnails/{id}` 从当前只读快照读取，不向页面暴露文件路径。同一 `RecentClips/thumb.png` 使用稳定 ID，因此最近录像即使被拆成多段会话也会展示并缓存同一张图。

### 手动刷新

```http
POST /api/v1/refresh
```

`refresh` 只收敛数据盘和 Gadget 生命周期；立即创建新快照并更新媒体索引使用：

```http
POST /api/v1/scan
```

手动扫描不受自动失败退避限制；成功后视频列表原子切换到新快照，失败时继续使用最后一个可用快照。

### 虚拟盘容量与历史空间回收

`GET /api/v1/storage` 同时返回两层容量：`snapshot_space` 是承载镜像、快照和导出文件的外层 XFS，`media_snapshot.volume_space` 是车机实际使用的 exFAT 虚拟盘。页面主容量显示后者，并在说明中保留外层 XFS 可用值，避免删除录像后把两层空间混为一谈。

网页删除会在内核 exFAT 挂载上启用 `discard`，使后续释放的簇尽量直接穿透 file-backed loop 并返还外层空间。历史版本已经删除但没有 discard 的空间使用独立维护接口：

```http
POST /api/v1/storage/reclaim
Content-Type: application/json

{"confirm_otg_disconnected":true}
```

回收必须进入媒体维护窗口，先解绑 Gadget、清理快照、运行 `fsck.exfat` 并解除 loop，再依据 exFAT Allocation Bitmap 对明确标记为空闲的连续簇执行 hole punch。普通“立即刷新”只更新只读快照和两层容量，不得隐式触发 Gadget 断开或空间打洞。手动维护要求物理拔掉 OTG；开启媒体自动恢复后，接口会在完成或失败后安排温重启恢复。

## 边录边放自动验收

`teslabox-acceptance` 只读取 API，不触发刷新、扫描或任何设备写操作。它持续检查 Gadget、空间、快照轮换、视频数量和 1KiB HTTP Range，并以退出码 `0` 表示全部条件通过、`1` 表示验收失败、`2` 表示参数错误、`130` 表示用户取消。启用 Web 认证后，将管理密码放入本机 `TESLABOX_WEB_PASSWORD` 环境变量，工具会先登录且不会输出密码。

办公室模式不要求车机连接或视频增长，可先检查服务、快照轮换和 Range：

```powershell
go run ./cmd/teslabox-acceptance `
  --base-url http://192.0.2.25 `
  --duration 35s `
  --interval 5s
```

启用认证后的 PowerShell 示例：

```powershell
$env:TESLABOX_WEB_PASSWORD="你的管理密码"
go run ./cmd/teslabox-acceptance --base-url http://192.0.2.25 --duration 35s --interval 5s
Remove-Item Env:TESLABOX_WEB_PASSWORD
```

实车边录边放验收必须要求车机全程连接，并观察到新视频增长：

```powershell
go run ./cmd/teslabox-acceptance `
  --base-url http://192.0.2.25 `
  --duration 10m `
  --interval 5s `
  --require-host `
  --require-growth
```

自动化采集可以增加 `--output json`。验收期间仍应由手机播放一个已经写完的旧片段；工具的 1KiB Range 请求用于持续探测读取链路，不能代替真实播放器的持续播放。

工具默认绕过系统 HTTP 代理直连局域网 TeslaBox，避免代理错误接管 `192.168.x.x` 请求；只有确实通过代理访问设备时才增加 `--use-proxy`。

## 板端部署准备

以下文件已经提供，但不会自动安装、启用或启动：

- `deploy/systemd/teslabox.service`
- `deploy/udev/99-teslabox.rules`
- `configs/teslabox.env.example`

首次部署前需要确认：

1. 外接数据分区的 UUID 或唯一卷标。
2. `lsblk` 在系统中可用。
3. configfs 已挂载，并且 `/sys/class/udc` 中存在 UDC。
4. `/api/v1/storage` 返回的数据盘型号、序列号、UUID 和阶段符合预期。

systemd 和 udev 的安装、启用与启动应在板端验证后分别执行，避免一次安装脚本隐藏修改系统状态。

数据盘初始化和镜像创建仍必须保持为可单独审查和显式执行的步骤。主服务只会挂载身份、文件系统和目录均符合配置的数据盘；不会把未知磁盘初始化成 TeslaBox 数据盘。
