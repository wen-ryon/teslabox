# V0.1 实现现状与迁移说明

## 最终需求边界

V0.1 的最终目标是 [TeslaUSB 模拟模式](TESLAUSB_REQUIREMENTS.md)：TF 卡只运行 Debian；外接 128GB U 盘保存虚拟磁盘、快照和媒体索引；ROCK 3A 通过 OTG 向 Tesla 模拟 USB Mass Storage。

初版“直接挂载物理 Tesla U 盘”的主流程已经被移除。仓库保留了可复用的 TeslaCam 解析器、HTTP API、配置、系统命令边界和测试，并已切换到最终架构的只读预检状态机。数据盘显式初始化和 XFS reflink backing store 已完成，USB Gadget、backing image 和一致性快照仍未实现。

## 当前实现范围

当前代码完成以下闭环：

1. 按 UUID 或卷标发现唯一的外接数据分区，UUID 配置后不回退到卷标。
2. 检查数据盘文件系统、挂载点、backing store 目录和镜像是否就绪，不执行修复或创建。
3. 检查 configfs 和 UDC 是否可用，不创建或绑定 Gadget。
4. 通过状态机和 `/api/v1/storage` 暴露等待数据盘、准备、就绪、降级和故障状态。
5. 保留 `TeslaCam`、`TeslaTrackMode` 解析器和视频列表 API，后续接入只读快照。
6. 使用 udev 触发即时刷新，并使用周期轮询弥补事件丢失。
7. 通过独立的 `teslabox-init` 工具核对 USB 整盘稳定路径、传输类型、序列号、容量和占用状态，再显式创建 GPT、XFS reflink 文件系统和 backing store 目录。

常驻服务当前没有格式化、分区、创建目录、创建镜像、挂载数据盘或启用 Gadget 的副作用。

## V0.1 尚待实现

2. 使用 configfs 创建 USB Mass Storage Gadget 并绑定 UDC。
3. 创建写时复制快照，检查后只读挂载。
4. 从快照扫描、播放和下载已经完成的 MP4。
5. 完成 Gadget、快照和存储故障状态机的真实生命周期操作。

## 对 TeslaUSB 的借鉴

TeslaBox 参考了 [marcone/teslausb](https://github.com/marcone/teslausb) 的以下设计原则：

- 设备暴露、挂载、修复和归档必须有明确状态边界。
- 所有连接和断开操作必须幂等，允许服务在异常断电后重新收敛。
- 车端正在使用的 backing file 不能同时由 Linux 直接读写。
- 需要在线查看车端写入内容时，应读取一致性快照，而不是挂载正在导出的文件系统。
- `RecentClips`、`SavedClips`、`SentryClips` 和 `TeslaTrackMode` 应统一建立媒体索引。

ROCK 3A 的 USB Gadget 硬件可行性已经由用户确认。本项目采用支持一致性快照的方案：车辆持续写入原始镜像，TeslaBox 对快照副本执行检查、只读挂载和媒体扫描。正常在线查看不应断开车辆端 Gadget。

## 配置

配置样例位于 `configs/teslabox.env.example`。

关键配置：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `TESLABOX_HTTP_ADDR` | `:8080` | HTTP 监听地址 |
| `TESLABOX_DATA_UUID` | 空 | 数据分区文件系统 UUID，设置后优先且不回退卷标 |
| `TESLABOX_DATA_LABEL` | `TESLABOX` | 未配置 UUID 时使用的数据分区卷标（XFS 最多 12 个字符） |
| `TESLABOX_DATA_MOUNT_PATH` | `/var/lib/teslabox` | 期望的数据盘挂载点 |
| `TESLABOX_IMAGE_PATH` | `images/teslacam.img` | 数据盘内的虚拟磁盘相对路径 |
| `TESLABOX_SNAPSHOT_PATH` | `snapshots` | 数据盘内的快照相对路径 |
| `TESLABOX_INDEX_PATH` | `index` | 数据盘内的媒体索引相对路径 |
| `TESLABOX_STATE_PATH` | `state` | 数据盘内的高频运行状态相对路径 |
| `TESLABOX_CONFIGFS_PATH` | `/sys/kernel/config/usb_gadget` | USB Gadget configfs 路径 |
| `TESLABOX_UDC_PATH` | `/sys/class/udc` | UDC 类目录 |
| `TESLABOX_SCAN_INTERVAL` | `30s` | 媒体重扫间隔 |
| `TESLABOX_POLL_INTERVAL` | `3s` | 设备轮询间隔 |

服务不接受 `/dev/sdX` 作为持久配置。推荐初始化后记录 UUID；卷标重复时服务会进入故障状态，不会猜测目标磁盘。破坏性初始化参数不会放入常驻服务的自动启动路径。

## 数据盘初始化

初始化工具默认只输出计划，不会修改磁盘。`--device` 只接受 `/dev/disk/by-id/usb-*` 整盘稳定路径，`--confirm-serial` 必须与内核读取的整盘序列号完全一致；已挂载、swap、非 USB、非整盘或容量异常的设备都会被拒绝。

```bash
teslabox-init \
  --device /dev/disk/by-id/usb-_TESLADRIVE_071C4AAFBA8BEB80-0:0 \
  --confirm-serial 071C4AAFBA8BEB80
```

核对 dry-run 输出后，只有增加 `--execute` 并以 root 身份运行才会擦除磁盘。工具创建单一 GPT 分区、卷标为 `TESLABOX` 的 XFS 文件系统和 `images`、`snapshots`、`index`、`state` 目录。XFS 卷标最长为 12 字节，因此不能使用 13 字节的 `TESLABOX_DATA` 作为卷标。

## API

### 健康检查

```http
GET /healthz
```

### USB 与索引状态

```http
GET /api/v1/storage
```

### 视频列表

```http
GET /api/v1/videos
```

支持以下查询参数：

- `clip_type=recent|saved|sentry|track`
- `camera=front|back|left_repeater|right_repeater`
- `date=2026-07-15`
- `event=事件目录名`
- `limit=1..1000`
- `offset=0..N`

### 手动刷新

```http
POST /api/v1/refresh
```

兼容入口：

```http
POST /api/v1/scan
```

当前视频列表为空或仅用于解析器测试。完成快照模式后，API 路径保持兼容，数据源切换为当前可用的只读快照。

## 板端部署准备

以下文件已经提供，但不会自动安装、启用或启动：

- `deploy/systemd/teslabox.service`
- `deploy/udev/99-teslabox.rules`
- `configs/teslabox.env.example`

当前只读预检首次部署前需要确认：

1. 外接数据分区的 UUID 或唯一卷标。
2. `lsblk` 在系统中可用。
3. configfs 已挂载，并且 `/sys/class/udc` 中存在 UDC。
4. `/api/v1/storage` 返回的数据盘型号、序列号、UUID 和阶段符合预期。

systemd 和 udev 的安装、启用与启动应在板端验证后分别执行，避免一次安装脚本隐藏修改系统状态。

Gadget 模式不得直接复用当前自动挂载流程。数据盘初始化、Gadget 启用和 systemd 服务安装必须保持为可单独审查和执行的步骤。
