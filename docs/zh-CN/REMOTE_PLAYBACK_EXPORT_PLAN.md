# 远程播放、视频导出与云端访问开发流程

## 1. 文档目的

本文记录 TeslaBox 录像播放从局域网原画回放演进到低带宽远程访问的开发顺序、接口边界和验收条件，避免把播放器布局、转码、导出、WebRTC 和云端控制混成一个不可验证的大改动。

当前网页的多路播放会分别请求每个摄像头的原始 MP4。该方式适合 AP 或高速局域网，但远程播放消耗的是多路原始码率之和。三路、四路和六路远程播放的最终形态必须由 TeslaBox 合成为一条低码率视频后再发送。

## 2. 已确认需求

### 2.1 播放画质

- 支持自动、流畅、标准、高清和原画。
- 手动画质保持到用户重新选择，浏览器刷新后仍然生效。
- 自动画质综合传输路径、实测吞吐、RTT、缓冲时长、卡顿次数和设备转码负载判断。
- 降档要快，升档必须经过稳定观察，避免画质反复跳动。
- 在低码率转码尚未实现前，不向用户伪装已经存在的画质档位。

建议初始档位如下，最终数值以 ROCK 3A 真机测试为准：

| 档位 | 建议输出 | 目标码率 |
| --- | --- | --- |
| 流畅 | 720p | 1.5～2 Mbps |
| 标准 | 720p/1080p | 约 3 Mbps |
| 高清 | 1080p | 5～6 Mbps |
| 原画 | 原始 MP4 | 不重新编码 |

### 2.2 播放布局

播放器支持以下模式：

| 模式 | 摄像头与布局 |
| --- | --- |
| 六路合成 | 左 B 柱、前视、右 B 柱、左翼子板、后视、右翼子板 |
| 四路合成 A | 左上前视、右上后视、左下右翼子板、右下左翼子板 |
| 四路合成 B | 第一行前视；第二行右翼子板、后视、左翼子板 |
| 三路合成 | 第一行前视；第二行右翼子板、左翼子板 |
| 单视角 | 用户选择的一路摄像头 |

画面默认保持原始比例，不裁剪；比例不一致的区域用黑色填充。缺失视角显示占位提示，不能阻止其余视角播放。

### 2.3 自定义导出

- 用户可选择录像、开始位置、导出时长、摄像头、布局和画质。
- 跨越多个一分钟文件时按统一时间轴拼接。
- 最终只生成一个完整 MP4。
- 单路且无需时间修正的导出可优先尝试无损拼接；多路合成必须重新编码。
- 导出是异步任务，支持排队、进度、取消、重启清理和空间预估。

不同视角存在 1～2 帧时差时，以 MP4 的 PTS/DTS 和首个可解码帧建立共同时间轴，以前视摄像头作为主时钟。提前的视角裁帧，延后的视角补黑帧或首帧，之后统一为固定帧率。额外提供按摄像头保存的帧偏移校准值，不依赖跨视角画面相似度猜测。

### 2.4 云端控制与 WebRTC

TeslaBox 主动向云端建立加密长连接，用于设备心跳、状态、WebRTC 信令和受限的业务指令。控制通道不承载六路原始录像，也不允许执行任意 Shell 命令。

媒体路径按以下顺序选择：

1. AP 或同一局域网直接访问。
2. WebRTC 通过 STUN 建立 P2P。
3. P2P 失败后通过 TURN 中继。

一个域名访问采用“每台设备固定域名 + 分流 DNS”：AP/局域网把同一设备域名解析到 TeslaBox，本地之外解析到云端入口。浏览器地址不变，ICE 协商决定媒体实际走局域网、P2P 还是 TURN。每台设备必须使用独立证书，不能把同一张通配符私钥复制到所有设备。

## 3. 分阶段开发流程

### 阶段 A：播放器布局与观测能力

- [x] 增加六路、四路 A、四路 B、三路和单视角切换。
- [x] 多路模式只加载布局实际使用的摄像头。
- [x] 保存用户上次选择的布局和画质偏好。
- [x] 展示当前网络路径、浏览器网络信息、实际媒体吞吐和缓冲时长（浏览器侧第一版）。
- [x] 记录主播放轨道的卡顿次数，为自动画质提供输入。

验收条件：

- 三路模式只有三个视频内容请求，四路模式只有四个。
- 切换布局后播放位置不回到开头。
- 手机端和桌面端布局均无溢出，缺失摄像头有明确提示。
- 页面明确区分浏览器估算带宽和实际媒体吞吐。

### 阶段 B：ROCK 3A 媒体能力基准

- [ ] 采集真实 Tesla MP4 的编码、分辨率、帧率、PTS/DTS 和关键帧间隔。
- [ ] 验证 FFmpeg 是否能调用 Rockchip MPP 解码和编码。
- [ ] 分别测试单路、三路、四路和六路解码加一路编码。
- [ ] 记录 CPU、内存、温度、功耗、帧率和长时间稳定性。

验收条件：至少连续运行 30 分钟，不发生持续降频、内存增长或服务异常。未通过前不得默认开启板端多路转码。

### 阶段 C：低码率合成与自动画质

- [ ] 建立统一布局描述，供网页预览和板端合成共用。
- [ ] 生成流畅、标准、高清多档输出。
- [ ] 录像回放采用支持分段和切档的 HLS/CMAF 或等价方案。
- [ ] 自动画质实现快速降档、延迟升档和手动锁定。
- [ ] 转码不可用时安全回退到单路原画，而不是让六路原画压垮远程链路。

### 阶段 D：自定义导出

- [ ] `POST /api/v1/exports` 创建导出任务。
- [ ] `GET /api/v1/exports/{id}` 查询状态和进度。
- [ ] `DELETE /api/v1/exports/{id}` 取消任务。
- [ ] `GET /api/v1/exports/{id}/download` 下载结果。
- [ ] 默认只允许一个任务执行，并设置有界队列。
- [ ] 使用临时文件生成，完成后原子重命名；失败或重启后清理遗留文件。

### 阶段 E：云端控制和 WebRTC

- [ ] 设计每台设备的身份、证书、用户授权和审计模型。
- [ ] 实现出站控制长连接和断线指数退避。
- [ ] 实现 WebRTC 信令、STUN、P2P 路径检测。
- [ ] 部署 TURN 并验证移动网络、对称 NAT 和运营商网络。
- [ ] 实现设备固定域名、分流 DNS 和独立证书签发。

## 4. 自动画质判定原则

自动模式不能只读取 `navigator.connection`。该接口只作为提示，还要使用真实媒体请求的下载字节和耗时计算吞吐，并持续观察播放器缓冲区。

- 缓冲不足或连续卡顿时立即降一档。
- 实测吞吐低于当前目标码率的 1.25 倍时禁止升档。
- 实测吞吐高于下一档目标码率的 1.5 倍并稳定 20～30 秒后才允许升档。
- TURN、DERP 或 Peer Relay 路径默认从标准或流畅档开始。
- AP 和局域网可以优先高清，但不能忽略设备转码负载。

## 5. 安全和资源边界

- 云端指令使用明确的类型和参数白名单，不提供远程 Shell。
- 导出队列、转码进程、临时空间和日志大小必须有上限。
- 所有后台任务都必须支持取消和超时。
- 外接数据盘空间不足时优先保障 Tesla 写入，不启动新导出任务。
- TURN 只作为兜底，必须配置用户鉴权、流量限制和过期凭证。

## 6. 当前执行位置

当前从阶段 A 开始。阶段 B 需要在实际 ROCK 3A 和真实 Tesla 录像上执行，阶段 C 以后不能用 Windows 本机构建成功代替板端性能验收。
