# TeslaBox 0.1.31 本机 AP 自动化

本版本新增仅供 TeslaBox 板内自动化脚本使用的 AP 热点控制能力。该版本先通过 beta 通道验证不同无线网卡、驱动和 AP+STA 并发能力的实际表现；程序版本始终为 `0.1.31`。

## 本机自动化接口

- 新增 `teslaboxctl`：它与 TeslaBox 主程序使用同一个二进制，可用 `teslaboxctl -v` 确认当前版本。
- 自动化接口只监听板内 Unix Socket，不会通过热点、局域网或 FRP 暴露，也不需要保存管理页面密码。
- 脚本只能调用固定的 AP 状态、频段/信道和租约操作；接口不接受任意命令、程序路径或 Shell 参数。

## AP 租约与权限控制

- GPS 等自动化脚本可按来源申请、续期和释放临时 AP 租约；租约到期会自动失效。
- 自动化租约不会更改开机自动连接策略，也不会关闭用户在设置中心手动开启的热点。
- 新增 `teslabox-automation` 用户组。控制 Socket 默认仅允许 root 与该组成员访问；没有该组时会安全降级为 root 专用权限。

## 频段、信道与并发能力

- 支持在 AP 运行期间调整热点首选频段和信道，已连接客户端可能会短暂重连。
- 设置前会根据无线硬件能力、监管域和 AP+STA 并发约束校验可用频段与信道，不会强行写入不受支持的配置。
- 对仅同信道并发、独立无线设备和未知能力分别采取对应的安全限制；无法安全并发时会拒绝操作。

## 失败处理与内测重点

- AP 启动、配置或租约恢复失败会保留原有配置并返回明确错误，避免自动化脚本破坏用户已有热点状态。
- beta OTA 验收应从旧版本完成检查、下载、安装和重启；重启后确认 `teslaboxctl -v`、GPS 脚本调用、AP 开关、频段/信道设置及 USB Gadget 状态。
- 本次普通 OTA 不包含内核、无线驱动、设备树、systemd unit 或任意脚本包；不同无线网卡和驱动的并发结果以实机验收为准。

## 回退

更新助手在健康检查失败时会自动恢复上一个程序版本。不要在车机通过 OTG 正在写入时安装或重启。
