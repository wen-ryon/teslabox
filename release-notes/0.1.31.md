# TeslaBox 0.1.31 本机 AP 与 WiFi 自动化

本正式版基于已完成用户使用验证的 `0.1.31-rc.4` 源码发布，程序版本为 `0.1.31`。新增仅供 TeslaBox 板内可信自动化脚本使用的 AP 热点与 WiFi 控制能力。

## 本机自动化接口

- 新增 `teslaboxctl`：它与 TeslaBox 主程序使用同一个二进制，可用 `teslaboxctl -v` 确认当前版本。
- 自动化接口只监听板内 Unix Socket，不会通过热点、局域网或 FRP 暴露，也不需要保存管理页面密码。
- 脚本只能调用固定的 AP 与 WiFi 操作；接口不接受任意命令、程序路径或 Shell 参数。

## AP 租约与权限控制

- GPS 等自动化脚本可按来源申请、续期和释放临时 AP 租约；租约到期会自动失效。
- 自动化租约不会更改开机自动连接策略，也不会关闭用户在设置中心手动开启的热点。
- 新增 `teslabox-automation` 用户组。控制 Socket 默认仅允许 root 与该组成员访问；没有该组时会安全降级为 root 专用权限。

## 频段、信道与并发能力

- 支持在 AP 运行期间调整热点首选频段和信道，已连接客户端可能会短暂重连。
- 设置前会根据无线硬件能力、监管域和 AP+STA 并发约束校验可用频段与信道，不会强行写入不受支持的配置。
- 对仅同信道并发、独立无线设备和未知能力分别采取对应的安全限制；无法安全并发时会拒绝操作。

## WiFi 自动化

- `teslaboxctl wifi list` 查看当前连接、已保存网络和可见网络缓存；`wifi scan` 主动扫描。
- `wifi connect` 支持通过 UUID 连接已保存网络，或通过 SSID 连接新网络。WPA/WPA2 密码从标准输入读取，不放入命令行参数。
- `wifi autoconnect enable|disable --uuid <UUID>` 调整已保存网络的自动连接策略，不会立即切换当前连接。
- 不支持 AP+STA 并发且热点正在占用无线网卡时，默认拒绝断开热点。明确指定 `--confirm-ap-disconnect` 才允许切换，应先确保有线管理可用。
- WiFi 操作同样受 root 与 `teslabox-automation` 用户组权限约束，只应授权可信脚本账号。

## 后续内测更新

- 设置中心可切换“稳定版 / 内测版”。选择内测版后支持发现、下载和安装后续 `x.y.z-rc.N` 版本。
- 正式版 `0.1.31` 可以升级到下一基础版本的 RC，例如 `0.1.32-rc.1`；同一基础版本的正式版高于其所有 RC，不会把 `0.1.31-rc.4` 作为更新。
- 通道选择会持久保存。切换后需要重新检查更新，下载中或已下载时不能切换通道。

## 失败处理与更新范围

- AP 启动、配置或租约恢复失败会保留原有配置并返回明确错误，避免自动化脚本破坏用户已有热点状态。
- 更新后可用 `teslaboxctl -v` 确认版本，并检查 GPS 脚本调用、AP 租约、WiFi、频段/信道设置及 USB Gadget 状态。
- 本次普通 OTA 不包含内核、无线驱动、设备树、systemd unit 或任意脚本包；不同无线网卡和驱动的并发结果以实机验收为准。

## 回退

更新助手在健康检查失败时会自动恢复上一个程序版本。不要在车机通过 OTG 正在写入时安装或重启。
