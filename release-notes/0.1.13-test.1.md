# TeslaBox 0.1.13 AP 重新启用热修复测试版

这是面向已安装 0.1.12 设备的增量测试更新，修复热点关闭并重启后在设置中心显示“不可用”、无法再次开启的问题。

## 问题原因

0.1.12 在关闭热点时会正确地把 `TeslaBox-5G` 的 `connection.autoconnect` 设置为 `no`。但启动脚本随后直接跳过虚拟 AP 接口创建，设置中心又把“配置绑定的接口暂不存在”解释为“硬件不支持 AP”，最终禁用整个热点表单。

典型现场状态是：物理无线接口 `wlan0` 正常连接上游 WiFi，`TeslaBox-5G` 配置仍存在且绑定 `ap0`，但系统中没有 `ap0`。这不是无线网卡、rfkill 或 NetworkManager 故障。

## 修复内容

- 热点关闭后仍执行无线 PHY、AP 模式、AP+STA 并发能力和允许信道探测。
- 支持 AP+STA 并发时只创建并准备未激活的虚拟 AP 接口；不会执行热点 `connection up`，不会广播 SSID。
- 只能在 STA 与 AP 之间互斥切换的网卡继续复用物理接口；上游 WiFi 已连接时不会为了准备热点而断开它。
- 不支持 AP 模式、没有无线网卡、无法读取 PHY 能力或没有允许信道时继续显示“不可用”，不会强行创建接口。
- 热点关闭状态只读取一次当前上游状态，不再为等待自动连接拖慢升级。
- 网页在线更新会识别并替换 0.1.12-test.1 的官方 AP 脚本，然后异步调度一次独立接口探测；无需重启板子即可恢复热点设置表单。
- 管理员自定义的 AP 脚本和 systemd unit 仍不会被覆盖。

## 更新后预期

更新服务重启后等待数秒并刷新设置中心。支持 AP 的设备应从“不可用”变为“已停用”，热点开关可以重新打开；热点保持关闭期间，上游 WiFi 连接不应中断。

## 安全边界

本次更新不重启 NetworkManager，不修改无线驱动或内核，不解绑或重新绑定 USB Gadget，也不修改 FFmpeg/RKMPP 工具链。USB Gadget 生命周期代码没有变更。
