# TeslaBox 0.1.12 WiFi/AP 兼容性热修复测试版

这是 0.1.11 测试版的替代版本，包含同一批 WiFi/AP 兼容性修复，并补上“关闭热点时必须同时关闭开机自动连接”的服务端约束。设备更新目录不会再提供 0.1.11 作为可选版本。

## 问题原因

- Debian 的普通 WiFi 自动连接由 NetworkManager 管理。0.1.9 加入的上游自动恢复会在断线时重复执行非交互式 `nmcli connection up`，与 NetworkManager 自己的认证流程竞争。
- 部分旧连接把 PSK 标记为 `agent-owned` 或 `not-saved`。无人值守服务无法向桌面密钥代理询问密码，因此即使密码没有改变，也会出现 `Secrets were required, but not provided`。
- 网页在线更新只替换主程序。0.1.7 安装到系统中的 AP 脚本和 systemd unit 仍可能无条件创建虚拟 AP 接口。
- “当前启用”和“开机自动启动”原本可以形成关闭当前热点但保留开机启动的组合；这与用户对“关闭热点”的预期不一致，重启后会表现为热点无法永久关闭。

## 修复内容

- 普通 STA 断线完整交还 NetworkManager 自动恢复；TeslaBox 不再后台强制扫描、挑选网络、固定 BSSID 或重复执行 `connection up`。
- 仅在单射频 AP+STA 必须共用信道时协调热点信道；解除 NetworkManager 的临时自动连接阻止后，由系统完成认证和接入点选择。
- 设置中心识别系统无法读取密码的已保存网络，明确提示重新输入；重新保存后将密码设为系统持有。
- 新建 WiFi 配置显式使用系统持有的 PSK，适合无桌面的开机自动连接。
- NetworkManager 因虚拟 AP 接口创建、删除或无线网卡热插拔而改变设备清单时，立即重建事件监听。
- 网页更新后的主程序会迁移已知官方旧版 AP 脚本、systemd unit 和 udev 规则；用户自定义文件不会被覆盖。
- 关闭热点会由前端和服务端同时强制关闭 `connection.autoconnect`；即使旧页面或其他客户端仍提交自动启动，重启后热点也不会自行恢复。
- AP 初始化脚本先读取热点配置的自动连接开关；热点已关闭时不会创建虚拟接口。
- AP 迁移不启动或重启热点，不重启 NetworkManager，也不触碰 USB Gadget。
- 修正诊断日志脱敏规则，保留 NetworkManager 原始错误句式，同时继续隐藏真正的密码赋值。

## 更新后操作

如果设置中心把已保存网络标记为“需要重新输入密码”，点击“连接”并输入一次当前 WiFi 密码即可。密码会保存为系统连接密钥，之后由 NetworkManager 负责开机与断线自动重连。

## 更新范围

网页在线更新只下载和替换签名验证后的 TeslaBox 主程序。新版主程序首次启动时会按官方旧文件摘要安全迁移 AP 脚本、systemd unit 和 udev 规则；不会修改内核、无线驱动、NetworkManager、FFmpeg/RKMPP 工具链或 USB Gadget 配置。
