# TeslaBox v0.1.7

本版本聚焦 TeslaUSB 写入稳定性、存储维护安全性、媒体中心和网络配置体验。升级或首装前请确认车机 OTG 当前没有写入；涉及媒体写入、删除、在线更新和存储初始化的操作都可能暂时中断 USB Mass Storage。

## USB 写入与恢复

- 优化 USB Mass Storage 写入路径：启用 `nofua=1`，并将脏页写回阈值设为后台 64 MiB、上限 256 MiB，降低连续写入一段时间后长时间卡顿的概率。
- 新增媒体自动维护恢复选项。用户明确开启后，上传或删除媒体时 TeslaBox 可以安全解绑 Gadget、执行写入并温重启恢复；默认仍保持“物理断开 OTG 后手动温重启”的保守模式。
- 在线更新默认安全解绑 Gadget；健康检查成功后自动温重启恢复。在线更新仅保留 `teslabox.previous.backup`，人工更新脚本仅保留 `/usr/local/bin/teslabox.backup`，避免系统盘积累历史二进制备份。

## 存储与媒体中心

- 设置中心可识别带稳定身份的 USB 存储和内部 NVMe，排除 TF 系统盘、已挂载盘和 swap 盘；已登记数据盘支持重新初始化。
- TeslaCam 镜像容量按磁盘容量规划，不再固定约 96 GiB；预留至少 20 GiB 或磁盘容量的 5%，并支持 TeslaCam 与 FAT32 MUSIC 分区比例配置。
- 媒体中心会扫描 Boombox、Wraps、LightShow 和 MUSIC 分区中由车机或电脑直接写入的文件；音乐改为目录浏览、面包屑和分页，每页 24 项，并支持删除。

## 网络与录像浏览

- 每个已保存 WiFi 连接可独立选择 DHCP 或静态 IPv4，支持地址、掩码、网关和最多四个 DNS；修改当前连接会立即重连。
- Tesla 录像文件名和无时区事件时间按车辆本地时区解析，默认 `Asia/Shanghai`，修复板子使用 UTC 时录像显示晚 8 小时的问题。
- 修正四路 A 翼子板顺序，改善多路合成黑边；新增“自动（高清）”“自动（标准）”“自动（流畅）”和“原画”画质策略。
- 录像快照根据是否有人浏览调整频率：空闲时默认每 5 分钟刷新，进入录像页后立即刷新并在 2 分钟内保持高频，降低空闲复制、挂载和扫描负担。

## 首装可靠性

- 首装脚本随 Gitee 首装包内置并校验 Radxa APT 签名密钥环，不再依赖访问 GitHub。
- 安装时可选择切换清华大学 Debian 镜像或保留现有镜像；两种选择都会禁用已下线的 `bullseye-backports`，且不会改写 Radxa、Tailscale、VSCodium 等第三方源。被修改的 APT 源会备份到 `/var/backups/teslabox/apt-sources/`。
- 首装结束会同时提示当前 IP 管理地址和 `http://teslabox.local/`；mDNS 受客户端支持和本地 DNS 劫持策略影响，无法访问时请使用 IP 地址。

## 已知限制与操作提示

- `nofua=1` 以较弱的主机强制落盘语义换取写入性能；突然断电时最近一小段写入数据的风险更高，建议用大文件连续写入完成长时间实车验证。
- 媒体自动维护和在线更新都会令车机或电脑短暂失盘，无法消除 OTG 热插拔可能造成的硬件掉电或反冲风险；不需要自动恢复时请保持该选项关闭。
- 大容量 NVMe 完整初始化、媒体直接写入后的目录分页/删除、静态 IPv4 重连、低功耗快照以及更新成功或失败后的自动恢复仍需完成板端完整回归。
- 静态 IPv4 填写错误会导致当前页面断开，可通过 TeslaBox AP 或其他网络重新访问并改回 DHCP。
- 初始化会擦除整块目标盘；最小支持 32 GiB，16 GiB 傲腾盘会被拒绝，MBR 镜像上限约为 2 TiB。
