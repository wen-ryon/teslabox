# TeslaBox 0.1.17 虚拟盘空间回收测试版

这是面向已安装 0.1.16 设备的灰度测试更新，重点验证网页删除录像后，TeslaCam 虚拟盘内部空闲空间能够安全返还给外层 XFS 数据盘。请先在少量 ROCK 3A 设备上验证，不建议立即全量更新。

## 空间回收

- 设置中心新增“回收旧空间”。操作会停止 USB Gadget、清理只读快照、检查 exFAT、释放 loop 设备，再依据 exFAT 分配位图只回收确认未分配的簇。
- 回收通过对稀疏镜像执行 hole punch 返还外层 XFS 物理区块，不改变虚拟盘逻辑容量，也不移动仍在使用的录像数据。
- 对 MBR、exFAT 启动区、FAT 簇链、分配位图、关键元数据簇和所有偏移执行边界校验；布局损坏、位图异常或碎片数量超过安全上限时直接拒绝回收。
- 回收结果区分“位图确认的候选空间”和“外层实际释放空间”。如果外层文件系统不支持打洞，会明确失败，不会继续修改镜像。

## 后续录像删除

- 内核 exFAT 挂载优先启用 `discard`，网页后续删除录像时可直接把释放簇传给 file-backed loop，并返还外层镜像区块。
- 旧内核不支持 `discard` 时自动回退到普通内核挂载；没有内核 exFAT 时继续回退到 `exfat-fuse`，不会因为空间优化破坏原有删除功能。
- 普通录像刷新仍然只创建只读快照和更新索引，不停止 Gadget、不执行空间回收，也不触发重启。

## Gadget 生命周期

- 自动维护从开始后使用独立的限时上下文；浏览器关闭或 HTTP 请求断开不会中止 loop 释放和温重启预约。
- 即使空间回收超时或失败，恢复阶段也使用新的独立超时，尽量确保 Gadget 保持解绑并通过下一次温重启安全恢复。
- 手动维护模式仍要求先物理拔掉车机或电脑 OTG，避免主机可能仍在写盘时修改镜像。

## 页面显示

- 首页主要容量改为 TeslaCam 虚拟盘内部 exFAT 可用空间，同时显示承载镜像的外层 XFS 可用空间，避免把两层容量混为一谈。
- 设置中心的“立即刷新”不会回收空间；历史删除产生的外层占用必须显式点击“回收旧空间”。

## 测试范围与观察项

- 本版只替换签名校验后的 TeslaBox ARM64 主程序及其内嵌网页，不修改内核、systemd、udev、AP 脚本、NetworkManager 或 FFmpeg/RKMPP 工具链。
- 请验证回收前后首页外层 XFS 可用空间、操作结果中的实际释放字节、温重启后 Gadget 重新枚举，以及车机继续录像和网页播放是否正常。
- 回收期间不要断电、拔出数据盘或连接新的 USB 主机。ROCK 3A 仍必须遵守独立 Type-C 供电和 OTG 安全接线顺序。
