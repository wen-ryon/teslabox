# TeslaBox 0.1.10 六路原画播放热修复测试版

这是面向已安装 0.1.9 测试版设备的增量更新，修复六路原画播放在拖动进度条或切换录像分钟时出现整组画面失效的问题。

## 修复内容

- 为播放器切源增加代次隔离。旧的异步媒体加载即使延迟结束，也不能再暂停、释放或覆盖新一次拖动正在使用的视频元素。
- 换段和拖动前主动释放上一批辅助视角及其 HTTP Range 请求，避免旧请求长期占用浏览器连接。
- 六路原画加载改为只预取元数据，并将元数据等待窗口从 4 秒放宽到 12 秒，降低多个视角同时建链时的误判。
- 单个辅助视角加载失败时保留其余已成功加载的视角，不再销毁整组六路画面；界面会明确显示“画面加载失败”，不再误报为录像文件缺失。
- 主视角或整组加载失败后彻底清理媒体源，下一次切换视角、布局或分钟会重新建链，不再保留只剩前视的半失效状态。
- 修正显式选择“原画”时仍提示“正在尝试压缩画质”的误导文案；只有“自动”画质才会实际进入板端合成降级流程。
- 客户端日志会记录具体失败视角、媒体错误码和就绪状态，便于继续区分浏览器解码、链路和源文件问题。

## 现场日志说明

原日志中的 `media_error_code=4`、`ready_state=0` 表示浏览器没有成功建立当前媒体源。故障期间 `group_id` 始终相同，且没有板端实时合成开始日志；因此不是周期性 TeslaCam 快照切换导致，也没有真正进入压缩画质。原播放器在任意一路加载失败后会移除所有辅助元素但保留前视元素，正好造成“只剩前视、其他视角显示缺失”，直到下一分钟更换全部视频 ID 后才恢复。

## 更新范围

网页在线更新只替换 TeslaBox 主程序及其中嵌入的管理页面，不修改内核、驱动、NetworkManager、systemd、USB Gadget 配置、AP 初始化脚本或 FFmpeg/RKMPP 工具链。
